# 发票票种识别：专票 / 普票 / 数电票 / 红字

> 每一张发票 PDF 都要**先识别票种**，再决定税额处理（可抵扣与否）、费用归类与台账列示。识别依据以发票页面文字为准，文件名仅作参考。

## 票种一览与处理差异

| 票种 | 页面名称特征 | 税额处理 |
|---|---|---|
| 增值税专用发票（纸质/电子） | 标题"增值税**专用**发票"；**数电票（专票）**标题为"电子发票（增值税专用发票）" | 一般纳税人可认证抵扣（进项税额单列）；小规模纳税人不可抵扣 → 计入成本 |
| 增值税普通发票（纸质/电子） | 标题"增值税**普通**发票"；数电票（普票）"电子发票（增值税普通发票）" | 税额不可抵扣（除通行费电子普票、注明旅客身份信息的运输凭证等特殊规定） |
| 机动车销售统一发票 / 二手车销售统一发票 | 特殊票种标题 | 按机动车/二手车专用规则处理，不得套用普票规则 |
| 定额发票 | 无计税信息，仅金额栏 | 全额计入费用，无税额 |
| 支付/电子回单 | 标题"电子回单/交易回单"，如支付宝、银行回单；无发票要素 | **非发票**：不可作为抵扣/入账凭证，仅作付款凭证存档（辅助对账） |
| 行程校验单 | 标题"行程校验单/航旅纵横" | **非发票**：仅证明行程，入账需配套正式发票 |
| 红字发票 | 页面含"红字发票"，或备注"红字"；冲减原蓝字票 | 作废/冲减：正负相抵，不构成费用 |

## 识别方法（由强到弱）

1. **页面标题（最可靠）**：逐页提取 PDF 文本，正则匹配：
   - `电子发票[（(]?增值税专用发票` 或 `增值税专用发票` → **专票**
   - `电子发票[（(]?增值税普通发票` 或 `增值税普通发票` → **普票**
   - `红字发票` / `红冲` / 负数票价 → **红字票**
   - `铁路电子客票` → **铁路电子客票**（可按规定抵扣的客运凭证）
   - `电子回单` / `行程校验单` → **非发票凭证**
   - `机动车销售统一发票`、`二手车销售统一发票` → 特殊票种
2. **专票版面特征**（标题被裁切/扫描件时辅助）：
   - 购买方/销售方各含四项要素：名称、纳税人识别号、地址电话、开户行及账号
   - 有"税率 + 税额"列，且区分"金额"与"税额"两栏
   - 普票通常只有名称+识别号（简化版），无开户行账号栏
   - ⚠️ 弱证据：数电票部分渠道对普票也展示开户行账号，不能单独据此定票种
3. **文件名启发式（仅参考）**：文件名含"专票/专"→疑似专票；"普票/普"→疑似普票；"红"→疑似红字（"已冲红"等需结合页面判定）；"回单"→非发票凭证
4. **二维码/查验平台**（必要时）：扫描发票二维码或到全国增值税发票查验平台查验票种真伪

> 自动化工具：`skills/financial-check/scripts/invoice_detect.py` 可批量识别票种与关键字段（依赖 pdfplumber）。

## 判定流程

```
1. 提取 PDF 文本（pdfplumber）→ 找票种标题关键词
2. 匹配成功 → 确定票种，按上表处理税额
3. 文本缺失（扫描件）→ 依据版面特征 + 文件名 + 查验平台辅助
4. 仍无法确定 → 标注"待确认"，询问用户，不得按默认票种处理
```

## 与纳税人身份的联动

| | 小规模纳税人 | 一般纳税人 |
|---|---|---|
| 专票（含数电专票） | 税额**计入成本**，不可抵扣 | 税额**进项税额**，可认证抵扣 |
| 普票 | 税额计入成本或费用 | 税额不可抵扣（特殊凭证除外） |
| 红字票 | 冲减原费用 | 冲减进项税额/费用 |

**铁律**：金额与税额必须与 PDF 原文一致（核对链第 1 条）；票种识别失败率>0 时不得出具报表，先补齐识别。
